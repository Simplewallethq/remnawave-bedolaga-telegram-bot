# Копикэт-витрина: как поставить новый бренд

Копикэт — это тот же образ бота с другим `.env`. Отдельная ветка не нужна и
не заводится: расхождение веток означает, что каждый багфикс придётся
черешнить руками в каждую витрину.

## Переменные

| Переменная | Значение | Что делает |
|---|---|---|
| `VPN_BRAND_NAME` | `Shuka` | Имя приложения во всех текстах. Пусто = остаёмся `Leto` |
| `BRAND_HAS_OWN_APP` | `false` | Нет своего приложения: только Happ/Incy, кнопка «Скачать <бренд>» не предлагается |
| `BRAND_RAYS_ENABLED` | `false` | Убирает лучи, сообщения о них и магазин наград |
| `BRAND_CHANNEL_ENABLED` | `false` | Убирает блок «подпишись на канал» из главного меню |
| `SUPPORT_USERNAME` | `@shuka_support` | Саппорт-бот витрины, задаётся в одном месте |
| `LOGO_FILE` | `shuka_logo.png` | Своя картинка |
| `REFERRAL_COMMISSION_PERCENT` | `50` | Реферальная ставка |

## Как работает подмена имени

Локали остаются написанными с «Leto». Подстановка происходит в
`Texts._get_value` — единственной точке, через которую проходит любой текст,
включая инлайновые дефолты в хендлерах. Поэтому новый текст, написанный
завтра, тоже подхватится: специально ничего помечать не нужно.

Регистр сохраняется по форме: `LETO` → `SHUKA`, `leto` → `shuka`,
`Leto` → `Shuka`.

**Что подстановка не трогает намеренно:** `letovpn.com`, `com.letovpn.ios`,
`@letovpn_bot`. Это адреса, а не название: переименование их сломает ссылку,
bundle id и хэндл. Домены витрины задаются своими переменными.

## Новая витрина за один файл

```bash
cp .env .env.shuka
# в .env.shuka меняем: BOT_TOKEN, VPN_BRAND_NAME, SUPPORT_USERNAME,
# LOGO_FILE, BRAND_* флаги
```

Затем отдельный сервис в `docker-compose.yml` с тем же образом и
`env_file: .env.shuka`.

## Правила и политика

`ServiceRule` хранится в БД с разбивкой по языкам и правится через админку.
Текст правил проходит через ту же подстановку, поэтому упоминание бренда в
правилах подставится само. Если витрина работает на своей базе — правила у
неё свои с самого начала.
