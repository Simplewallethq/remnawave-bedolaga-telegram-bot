# Автообновление приложения — гайд для разработчика клиента

Бэкенд отдаёт манифест обновления десктопного приложения: версия, ссылка на
установщик, хеш и признак обязательности. Эндпоинт **публичный** — апдейтер
проверяет обновления до логина и когда токен протух.

Всё содержимое манифеста задаётся администратором в веб-админке (категория
**«🖥️ Обновления приложения»**) и применяется без перезапуска бэкенда: выпуск
релиза = смена версии, ссылки и хеша в админке.

---

## 1. Эндпоинт

```
GET {API_BASE}/cabinet/app/update?platform=windows&current=1.4.0
```

Авторизация не нужна — заголовок `Authorization` можно не слать вовсе.

| Параметр | Обяз. | Значение |
|---|---|---|
| `platform` | нет | `windows` (по умолчанию). Принимается алиас `pc`. Другие платформы пока отдают `404` |
| `current` | нет | Текущая версия клиента, напр. `1.4.0`. Если передана — сервер сам посчитает `updateAvailable` и `mandatory` |

Передавать `current` — рекомендуемый путь: сравнение версий тогда живёт в одном
месте, и логику обязательных обновлений можно менять на бэкенде без выката
нового клиента.

### Ответ `200`

```json
{
  "platform": "windows",
  "version": "1.4.2",
  "url": "https://cdn.example.com/downloads/setup-1.4.2.exe",
  "mirrors": [
    "https://github.com/org/app/releases/download/v1.4.2/setup-1.4.2.exe"
  ],
  "sha256": "9f2c…",
  "minSupportedVersion": "1.3.0",
  "notes": "Починили автозапуск при старте Windows",
  "updateAvailable": true,
  "mandatory": false
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `version` | string | Версия доступного релиза |
| `url` | string | **Основная** ссылка на установщик. Пробуйте её первой |
| `mirrors` | string[] | Запасные ссылки (может быть пустым). Идти по порядку, если основная недоступна |
| `sha256` | string \| null | SHA-256 установщика в нижнем регистре. См. раздел «Безопасность» |
| `minSupportedVersion` | string \| null | Версия, ниже которой обновление обязательное |
| `notes` | string \| null | Changelog для окна апдейтера. Обычный текст, не HTML — не рендерите как разметку |
| `updateAvailable` | bool \| null | `null`, если `current` не передан или не распознан |
| `mandatory` | bool \| null | `true` только если апдейт есть **и** `current < minSupportedVersion` |

Ответ кешируемый: `Cache-Control: public, max-age=300`.

### Ответ `404`

```json
{ "detail": "Update channel is not configured for this platform" }
```

Отдаётся, когда канал обновлений выключен, не заполнен (нет версии или ссылки)
либо запрошена неподдерживаемая платформа. **Это не ошибка** — трактуйте как
«обновлений нет»: молча выходите из проверки, ничего не показывая пользователю.
Админ может временно выключить канал, если релиз оказался битым.

## 2. Формат версий

Сервер разбирает **ведущую числовую часть** версии: `1.4.2` → `(1, 4, 2)`.

- Суффиксы предрелизов игнорируются: `1.4.2-beta.1` считается равным `1.4.2`.
- Разное число компонентов сравнивается корректно: `1.4` < `1.4.1`, `1.4.0` == `1.4`.
- **`v1.4.2` не распознаётся** — из-за ведущей `v` вернётся `updateAvailable: null`.
  Шлите в `current` голую версию, без префиксов и метаданных сборки.

Если `updateAvailable` пришёл `null`, а сравнить надо — сравнивайте сами
`version` и `minSupportedVersion` с локальной версией по тем же правилам.

## 3. Алгоритм апдейтера

```
1. Проверка при старте приложения + раз в несколько часов в фоне.
2. GET /cabinet/app/update?platform=windows&current=<своя версия>
   - 404 или сетевая ошибка → выйти молча, повторить в следующий цикл.
3. updateAvailable == false → выйти.
4. Скачать установщик: url, при неудаче — mirrors по порядку.
5. Проверить sha256 скачанного файла.
   - не совпал → удалить файл, попробовать следующее зеркало;
   - не совпал нигде → НЕ запускать ничего, залогировать, выйти.
6. Проверить цифровую подпись установщика (Authenticode).
7. mandatory == true → обновляться без спроса, иначе предложить пользователю
   (с текстом из notes) и запомнить «напомнить позже».
8. Запустить установщик, закрыть приложение.
```

Ключевые правила:

- **Не поллить чаще раза в час.** Ответ статический и кешируется на 300 секунд;
  частые проверки не дают ничего, кроме нагрузки.
- **Сетевые ошибки — не повод для диалога с пользователем.** Проверка обновлений
  фоновая, тихий ретрай в следующем цикле.
- **`mandatory` не должен превращаться в кирпич.** Если обязательное обновление
  не удалось скачать или проверить — дайте пользователю работать дальше и
  повторите позже; не блокируйте запуск приложения.
- Если пользователь отложил необязательный апдейт, не показывайте окно повторно
  для той же `version` в рамках одной сессии.

---

## 4. Безопасность

Апдейтер скачивает и запускает `.exe` — это самая опасная часть клиента.
Минимальные требования:

1. **Проверять `sha256` до запуска.** Зеркала (в том числе GitHub Releases) не
   контролируются нами полностью; подмена файла на зеркале без проверки хеша =
   выполнение чужого кода на машине пользователя. Если `sha256` в манифесте
   `null` — не запускайте автоматическую установку, ограничьтесь ссылкой
   «скачать вручную».
2. **Проверять цифровую подпись** установщика в дополнение к хешу.
3. **Только HTTPS**, без отключения проверки сертификатов и без редиректов на
   `http://`.
4. Скачивать во временный каталог, недоступный на запись другим пользователям,
   и запускать оттуда только после успешных проверок.

## 5. Что за поля видит администратор

Соответствие полей ответа настройкам в админке — на случай вопросов «почему
клиент не видит релиз»:

| Настройка | Поле ответа |
|---|---|
| `APP_UPDATE_WINDOWS_ENABLED` | канал целиком: `false` → `404` |
| `APP_UPDATE_WINDOWS_VERSION` | `version` (пусто → `404`) |
| `APP_UPDATE_WINDOWS_URL` | `url` (пусто → `404`) |
| `APP_UPDATE_WINDOWS_MIRRORS` | `mirrors` (список через запятую) |
| `APP_UPDATE_WINDOWS_SHA256` | `sha256` |
| `APP_UPDATE_WINDOWS_MIN_VERSION` | `minSupportedVersion` |
| `APP_UPDATE_WINDOWS_NOTES` | `notes` |

Изменения применяются сразу; у клиентов и промежуточных прокси возможна
задержка до 5 минут из-за `Cache-Control`.

## 6. Проверка руками

```bash
# текущее состояние канала
curl -s "https://api.example.com/cabinet/app/update?platform=windows" | jq

# как это увидит клиент версии 1.4.0
curl -s "https://api.example.com/cabinet/app/update?platform=windows&current=1.4.0" | jq

# хеш скачанного установщика (Windows PowerShell)
Get-FileHash .\setup-1.4.2.exe -Algorithm SHA256
```
